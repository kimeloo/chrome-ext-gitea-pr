## 1. 프로젝트 개요
* 배경: Gitea용 크롬 확장 프로그램이 드물어, 리뷰 요청·내 PR 등 나와 관련된 PR을 확인하려면 매번 Gitea 웹의 Pull Request 화면을 열어야 했습니다. [gitea-pr-usage](https://github.com/ehtjsv2/gitea-pr-usage)의 구조(Manifest V3, 토큰의 로컬 보관, 주소별 권한 요청)를 참고하여 제작했습니다.
* 핵심 역할:
  - 툴바 아이콘을 누르면 아이콘 아래에 **팝업(Action popup)** 이 열리고, 다른 곳을 클릭하면 자동으로 닫힙니다.
  - 열린 PR을 다섯 개의 탭으로 나누어 보여줍니다. 같은 PR이 여러 탭에 함께 나타날 수 있습니다.

    | 탭 | 의미 | Gitea API 필터 |
    |---|---|---|
    | 리뷰 요청 | 나에게 리뷰가 요청된 PR | `review_requested=true` |
    | 내 PR | 내가 연 PR | `created=true` |
    | 담당 | 나에게 할당된 PR | `assigned=true` |
    | 리뷰함 | 내가 리뷰한 PR | `reviewed=true` |
    | 멘션 | 나를 멘션한 PR | `mentioned=true` |

  - 탭 순서는 설정 페이지의 **탭 순서**에서 각 탭 오른쪽의 ≡ 버튼을 끌어서 바꿀 수 있습니다(≡ 버튼에 포커스한 뒤 ↑ ↓ 키로도 가능). 팝업을 열면 첫 번째 탭이 먼저 표시됩니다.
  - 팝업의 **설정** 버튼을 누르면 설정 페이지가 새 탭으로 열립니다. 설정 페이지에서는 Gitea 주소, 토큰, 테마(시스템/라이트/다크), 알림, 탭 순서, 표시 항목을 지정하며, 바꿀 때마다 오른쪽 미리보기에 팝업 모양이 즉시 반영됩니다. **저장**을 눌러야 실제 팝업에 적용됩니다. 왼쪽 메뉴를 누르면 해당 항목으로 바로 스크롤됩니다.
  - 표시 항목(기본값은 모두 켜짐, PR 번호와 제목은 항상 표시)

    | 그룹 | 항목 |
    |---|---|
    | 저장소·브랜치 | 소유자(조직), 저장소, 대상 브랜치(Base), 소스 브랜치(Head) |
    | 사람 | 작성자, 리뷰어, 담당자(Assignees), 참여자(Participants) |
    | 상태 | 리뷰 상태(승인/변경 요청/대기), CI 상태(Actions 등 커밋 상태 체크), 초안(Draft), 병합 가능 여부(충돌) |
    | 메타데이터 | 라벨, 마일스톤, 댓글 수, 변경 규모(+/− 줄, 파일 수), 생성일, 최근 업데이트, 마감일 |

  - **브라우저 알림(선택)**: 설정에서 켜면 지정한 주기(1·3·5·10·15·30·60분)마다 Gitea를 확인하여 운영체제 알림으로 알려줍니다. 기본값은 꺼짐이며, 알림을 누르면 해당 PR(또는 코멘트)이 새 탭으로 열립니다.
    - 기준은 Gitea 알림함입니다. watching 중인 저장소와 내가 참여한 PR의 소식을 받으며, 저장소를 만들면 Gitea 기본 설정(`AUTO_WATCH_NEW_REPOS`)에 따라 자동으로 watching 됩니다.
    - Gitea 웹에서 이미 읽은 알림과 내가 한 행동은 알리지 않습니다. 확인에 실패하면 알리지 않고 다음 주기에 다시 시도합니다.
    - 한 번에 6개 이상의 PR에 소식이 있으면 요약 알림 1건으로 묶고, 누르면 Gitea 알림함이 열립니다.

    | 알림 항목 | 조건 |
    |---|---|
    | 새 PR | watching 중인 저장소(내 저장소 포함)에 PR이 열렸을 때 |
    | 리뷰어 지정 | 나를 리뷰어로 지정했을 때 |
    | 담당자 지정 | 나를 담당자로 지정했을 때 |
    | 코멘트 | PR 대화에 코멘트가 달렸을 때 |
    | 리뷰 제출 | 승인 · 변경 요청 · 코드 리뷰 코멘트가 달렸을 때 |
    | 새 커밋 푸시 | PR에 새 커밋이 올라왔을 때 |
    | 머지 | PR이 머지되었을 때 |
    | 닫힘 / 다시 열림 | PR이 머지 없이 닫히거나 다시 열렸을 때 |
    | 체크 상태 | 내가 연 PR의 CI 체크가 성공 · 실패 · 경고로 바뀌었을 때 (대기 중으로 바뀌는 것은 알리지 않음) |

  - 모든 저장과 캐시는 브라우저 안(`chrome.storage.local`)에서만 이루어지며, 요청은 설정한 Gitea 주소로만 전송됩니다. 별도 서버·분석 도구·CDN을 사용하지 않습니다.

## 2. 기술 스택
- Language : JavaScript (ES Modules), HTML, CSS
- Framework : 없음 (Chrome Extension Manifest V3, 빌드 단계 없음)
- Database : `chrome.storage.local` (설정, 마지막 조회 결과 캐시, 알림 확인 상태)
- Build Tool : 없음 (테스트 실행에만 Node.js 18+ 사용)
- CI/CD : 없음

## 3. 디렉토리 구조

```
extension/                 ------ 압축해제 로드 대상 폴더
├── manifest.json          ------ 확장 매니페스트 (MV3)
├── background.js          ------ 설치 시 설정 페이지 열기, 알림 확인 주기(alarm) 관리
├── theme.js               ------ 테마 즉시 적용 (깜빡임 방지)
├── common.css             ------ 테마 변수, 팝업·미리보기 공용 스타일
├── popup.html/css/js      ------ 툴바 팝업
├── options.html/css/js    ------ 설정 페이지 (실시간 미리보기 포함)
├── icons/                 ------ 확장 아이콘 (icon.svg 원본 + PNG)
└── src/
    ├── settings.js        ------ 설정 기본값, 표시 항목 정의, 저장/불러오기
    ├── gitea.js           ------ Gitea REST API 클라이언트, 오류 메시지
    ├── notify.js          ------ 알림 이벤트 분류·문구 구성
    ├── poller.js          ------ 주기적 알림 확인과 확인 상태 저장
    ├── summarize.js       ------ 리뷰 상태·CI 상태·참여자 집계
    ├── dashboard.js       ------ 탭별 PR 조회와 상세 정보 수집
    ├── render.js          ------ PR 카드·탭 렌더링
    ├── icons.js           ------ Octicons SVG
    └── preview-data.js    ------ 설정 미리보기용 예시 데이터
preview/                   ------ HTML 미리보기 생성기 (가짜 크롬 화면, chrome.* 대체 구현, 가짜 Gitea)
test/                      ------ node:test 단위 테스트
dist/                      ------ 생성물 (git 제외)
```

## 4. 로컬 환경 세팅 및 실행 방법

1. 필수 설치 항목
   - Chrome (또는 Chromium 계열 브라우저)
   - Node.js 18 이상 (단위 테스트와 HTML 미리보기 생성 시에만 필요)
2. 확장 프로그램 설치
   1. 크롬에서 `chrome://extensions`를 엽니다.
   2. 오른쪽 위 **개발자 모드**를 켭니다.
   3. **압축해제된 확장 프로그램을 로드합니다**를 누르고 이 저장소의 `extension` 폴더를 선택합니다.
   4. 설치가 끝나면 설정 페이지가 자동으로 열립니다. 이후에는 툴바 아이콘 → 팝업의 설정 버튼으로 열 수 있습니다.
   5. 툴바의 퍼즐 아이콘에서 **Gitea PR Status**를 고정하면 아이콘이 항상 표시됩니다.
3. 토큰 발급 및 설정
   1. Gitea → 오른쪽 위 프로필 → **설정** → **애플리케이션**
   2. **새 토큰 생성**: 권한에서 `issue`, `notification`, `repository`, `user`를 **읽기**로 선택합니다. (`notification`은 브라우저 알림을 켤 때만 필요합니다)
   3. 설정 페이지에 Gitea 주소(하위 경로에 설치된 경우 경로 포함, 예: `https://example.com/gitea`)와 토큰을 입력하고 **저장**을 누릅니다.
   4. 크롬이 사이트 접근 권한을 요청하면 **허용**합니다. 저장 후 연결 상태에 `✓ {계정} 계정으로 연결되었습니다.`가 표시되면 정상입니다.
   5. 브라우저 알림을 받으려면 설정 페이지의 **알림** 섹션에서 **브라우저 알림 받기**를 켜고 주기와 알림 항목을 고른 뒤 저장합니다. 알림이 보이지 않으면 운영체제 알림 설정(Windows: 설정 → 시스템 → 알림)에서 Chrome 알림이 켜져 있는지 확인합니다.
4. 실행 명령어
   - 단위 테스트: `npm test`
   - 설치 없이 확인하는 HTML 미리보기 (자세한 내용은 6장 참고)
     - `npm run preview`: `dist/gitea-pr-status-preview.html` 파일을 생성합니다. 생성 시점의 스냅샷입니다.
     - `npm run preview:serve`: 로컬 서버(기본 `http://127.0.0.1:4173/`)로 제공합니다. 코드를 수정한 뒤 새로고침하면 반영됩니다.
   - 확장 코드 변경 후에는 `chrome://extensions`에서 확장의 새로고침 버튼을 누릅니다.

## 5. 운영 환경 세팅 및 실행 방법

- 크롬 웹 스토어에 등록하지 않으며, 4장의 압축해제 로드 방식으로만 사용합니다.
- 토큰은 이 브라우저의 `chrome.storage.local`에만 저장되며 크롬 동기화로 전송되지 않습니다. 다른 PC에서는 다시 설정해야 합니다.

## 6. 연동 시스템 및 시뮬레이터
- 연동 대상: 사용자가 설정한 Gitea 서버 1대 (REST API v1, 헤더 `Authorization: token {토큰}`)
- 지원 버전: Gitea 1.22 이상 기준으로 작성했습니다. 초안·변경 규모·코드 리뷰 댓글 수는 1.22부터 제공되며, 그 이전 버전에서는 해당 항목이 자동으로 숨겨집니다.

  | API | 용도 | 토큰 권한 |
  |---|---|---|
  | `GET /api/v1/user` | 연결 확인 | `read:user` |
  | `GET /api/v1/repos/issues/search` | 탭별 열린 PR 목록 | `read:issue` |
  | `GET /api/v1/repos/{owner}/{repo}/pulls/{index}` | 브랜치, 병합 가능 여부, 변경 규모, 리뷰 요청 대상 | `read:repository` |
  | `GET /api/v1/repos/{owner}/{repo}/pulls/{index}/reviews` | 리뷰 상태 | `read:repository` |
  | `GET /api/v1/repos/{owner}/{repo}/commits/{sha}/status` | CI 상태, 체크 상태 알림 | `read:repository` |
  | `GET /api/v1/repos/{owner}/{repo}/issues/{index}/comments` | 참여자 | `read:issue` |
  | `GET /api/v1/notifications/new` | 알림 권한 확인, 서버 시각 기준점 | `read:notification` |
  | `GET /api/v1/notifications` | 알림 대상 PR 변경 확인 (주기마다 1건) | `read:notification` |
  | `GET /api/v1/repos/{owner}/{repo}/issues/{index}/timeline` | 바뀐 PR의 코멘트·리뷰·머지 등 이벤트 | `read:issue` |

- 꺼져 있는 표시 항목·알림 항목에 필요한 API는 호출하지 않습니다.
- 알림 확인 요청 수: 바뀐 것이 없으면 주기마다 1건이며, 바뀐 PR마다 1~2건, 체크 상태 알림을 켜면 1건 + 내가 연 열린 PR 수 × 2건이 추가됩니다.
- 제약: Gitea REST API가 PR이 속한 프로젝트(Projects) 정보를 제공하지 않아 프로젝트 항목은 지원하지 않습니다. 아바타 이미지는 Gitea가 응답한 `avatar_url`에서 불러옵니다.
- 시뮬레이터(HTML 미리보기): 확장을 설치하지 않고도 팝업·설정·알림을 직접 조작하며 확인할 수 있는 수동 테스트용 페이지를 제공합니다.
  1. 실행 방법은 두 가지이며, 결과 화면은 같습니다.

     | 명령 | 여는 방법 | 코드 수정 반영 |
     |---|---|---|
     | `npm run preview` | `dist/gitea-pr-status-preview.html` 파일 하나가 생성됩니다. 확장 코드가 모두 포함되어 있으므로 더블클릭하여 크롬에서 열거나 다른 PC로 옮겨 열 수 있습니다. | 생성 시점의 스냅샷이므로 코드를 수정할 때마다 다시 실행해야 합니다. |
     | `npm run preview:serve` | 로컬 서버가 실행됩니다. 출력된 주소(기본 `http://127.0.0.1:4173/`, 사용 중이면 다음 포트)를 크롬에서 엽니다. 종료는 `Ctrl+C`입니다. 이 PC(127.0.0.1)에서만 접속할 수 있습니다. | 요청마다 다시 빌드하므로 브라우저에서 새로고침만 하면 됩니다. 단, `preview/build.mjs`와 `preview/serve.mjs`를 수정한 경우에는 서버를 다시 실행합니다. |

     - 보안 프로그램 등으로 크롬이 로컬 파일(`file://`)을 열지 못하고 `ERR_ACCESS_DENIED`가 표시되면 `npm run preview:serve`를 사용합니다.
  2. 확장의 실제 코드(`extension/`)를 수정 없이 그대로 실행하며, `chrome.*` API는 미리보기용 구현으로 대체하고 Gitea 응답은 내장된 예시 데이터로 대체합니다. 웹 페이지에서는 CORS 제약으로 실제 Gitea에 접속할 수 없으므로, 어떤 주소를 입력해도 예시 데이터를 사용합니다.
  3. 화면 왼쪽은 가짜 크롬 창(탭, 주소창, 확장 아이콘, 팝업, 권한 요청, 알림)이고, 오른쪽 시뮬레이터 패널에서 예시 설정 입력, 서버 상태(응답 없음·느린 응답·토큰 오류) 전환, 이벤트 만들기(코멘트·리뷰·머지·체크 결과 등), 알림 즉시 확인, 처음 설치 상태로 되돌리기를 할 수 있습니다.
  4. 설정과 예시 데이터는 브라우저의 `localStorage`에 저장되어 새로고침 후에도 유지됩니다. 예시 데이터(`preview/mock-gitea.js`)나 설정 기본값을 수정했다면 시뮬레이터의 **처음 설치 상태로 되돌리기**를 눌러야 반영됩니다.
  5. 미리보기로 확인할 수 없는 항목: 실제 크롬 확장 환경의 동작(백그라운드 서비스 워커 수명, 실제 권한 창과 운영체제 알림)과 실제 Gitea 서버의 응답·데이터는 확장을 설치하여 확인해야 합니다.
